# Notes about Lean

Protocol:
- Launch: lake exe repl from lean_project directory
- Send:   json.dumps(payload) + "\n\n"  (blank line terminator)
- Read:   lines until blank line, join, parse as JSON

Initialize proof:
- send: {"cmd": "theorem ... := by\n  sorry"}
- recv: {"sorries": [{"proofState": 0, "goal": "⊢ ..."}], "env": 0}

Apply tactic:
- send: {"tactic": "simp", "proofState": 0}
- recv (success):  {"proofState": 1, "goals": ["n : Nat\n⊢ n + 0 = n"]}
- recv (complete): {"proofState": 2, "goals": [], "proofStatus": "Completed"}
- recv (failure):  {"message": "Lean error:\n..."}

Branching:
- send two different tactics with same proofState N
- → get independent proofState N+1 and N+2

# How compiled libraries work in Lean

lake build
  └── compiles Mathlib source → .olean files on disk  (run once, takes hours)

lake exe repl
  └── boots a blank Lean process, waits for JSON commands  (takes ~1s)

{"cmd": "import LeanProject"}
  └── reads .olean files from disk into memory  (takes ~300s)
  └── returns {"env": 1}  ← now ring, linarith, etc. are all available

{"cmd": "theorem foo ...", "env": 1}
  └── elaborates in the Mathlib-loaded environment  (takes milliseconds)

# LEAN is not like python, and only contains a couple of major libraries
  - Init: ships with Lean itself, absolute core (basic types, logic primitives)
  - Batteries: extended standard library, data structures, more utilities etc...
  - Mathlib: the giant, covers most of mathematics; depends on Batteries
